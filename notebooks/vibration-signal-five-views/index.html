一段震動訊號的五種看法

用同一段模擬震動訊號，比較振幅門檻、峰值、斜率、滑動窗相似度與 rolling energy 五種時間域方法。

這頁在做什麼#

同一段震動訊號，可以用很多種方式看。這一頁用一段有四個運轉區間的模擬訊號。訊號分別用五種時間域方法來看：振幅門檻、峰值偵測、斜率、滑動窗相似度、rolling energy。每一種方法都只回答一部分問題。沒有一種能同時說出開始、結束與次數。

這是 PHM 系列的監測篇。下一篇〈馬達的八種壞法〉會把同一套取樣率與模擬器拿去做頻譜診斷。兩篇可以獨立讀，但一起看會更完整。

先把訊號造出來#

這段訊號的取樣率是 2000 Hz，長度 12 秒。背景是低振幅噪聲，中間有四段運轉區間。每段運轉的振幅、主頻與長度都不同，這樣才不會讓某一種方法剛好全對。

橘色底色是 ground truth。實務上不會有這個答案，這裡只是為了等一下算指標。

def simulate_signal(fs=FS, seed=7):
    rng = np.random.default_rng(seed)
    t = np.arange(0, DURATION, 1 / fs)
    x = 0.02 * rng.normal(size=t.size)
    truth = np.zeros_like(t, dtype=bool)

    segments = [
        (1.0, 2.0, 1.5, 8.0),
        (4.0, 5.0, 2.0, 12.0),
        (7.0, 8.0, 1.8, 6.0),
        (9.5, 10.5, 2.2, 10.0),
    ]
    for start, end, amp, freq in segments:
        mask = (t >= start) & (t < end)
        x[mask] += amp * np.sin(2 * np.pi * freq * t[mask])
        x[mask] += 0.35 * np.sin(2 * np.pi * (freq * 1.8) * t[mask])
        truth[mask] = True

    return t, x, truth

time, signal, truth = simulate_signal()

先定義評估方式#

訊號層級的指標把每個取樣點當成一個判斷，適合看「區間抓得準不準」。事件層級的指標只看「每個真實事件有沒有被抓到」，適合看峰值偵測。

intervals_from_mask() 把布林遮罩轉成連續區間。sample_metrics() 回傳 precision、recall、F1。event_metrics() 算峰值的事件 precision 與 event recall。

In [3]:
def intervals_from_mask(mask):
    mask = np.asarray(mask, dtype=bool)
    if not mask.any():
        return []
    edges = np.diff(mask.astype(int))
    starts = list(np.where(edges == 1)[0] + 1)
    ends = list(np.where(edges == -1)[0] + 1)
    if mask[0]:
        starts = [0] + starts
    if mask[-1]:
        ends = ends + [len(mask)]
    return list(zip(starts, ends))


def sample_metrics(pred, truth):
    pred = np.asarray(pred, dtype=bool)
    truth = np.asarray(truth, dtype=bool)
    tp = np.sum(pred & truth)
    fp = np.sum(pred & ~truth)
    fn = np.sum(~pred & truth)
    precision = tp / (tp + fp) if tp + fp else 0.0
    recall = tp / (tp + fn) if tp + fn else 0.0
    f1 = 2 * precision * recall / (precision + recall) if precision + recall else 0.0
    return float(precision), float(recall), float(f1)


def event_metrics(peaks, truth):
    truth = np.asarray(truth, dtype=bool)
    peaks = np.asarray(peaks, dtype=int)
    intervals = intervals_from_mask(truth)
    if len(peaks) == 0:
        return 0.0, 0.0
    precision = float(np.mean(truth[peaks]))
    recall = float(np.mean([any(s <= p < e for p in peaks) for s, e in intervals]))
    return precision, recall


def shade(ax, mask, color="tab:orange", alpha=0.18):
    ax.fill_between(time, -3, 3, where=mask, color=color, alpha=alpha, step="mid")

方法一：振幅門檻#

最直接的做法是看振幅有沒有超過某個門檻。這裡不做平滑，直接對絕對值取門檻 0.8。運轉區間會被抓到。但訊號每次穿越零點都會掉到門檻以下，所以一個事件會被切成很多小段。

方法二：峰值偵測#

第二種做法是先取包絡，再找峰值。包絡用 50 ms 的 moving average 平滑絕對值，然後用 find_peaks() 找局部最大值。這裡把最小距離設成 1 秒，讓每個運轉區間只留下一個代表峰。

峰值法很適合回答「發生了幾次」，但它不告訴你事件從什麼時候開始、到什麼時候結束。

方法三：斜率#

第三種做法看訊號變化有多快。先做 80 ms 的平滑，再算一階差分。運轉區間的高頻成分會讓斜率變大，背景噪聲的斜率則比較小。

斜率法對突發的高頻很敏感，但門檻很難調。太低會把噪聲抓進來，太高會漏掉振幅較小的事件。

滑動窗是什麼#

滑動窗把訊號切成固定長度的片段，每次往前移動一小步。每個片段可以算一個分數：RMS、能量、與模板的距離，或任何你想比較的特徵。

下面這支動畫用 0.5 秒的窗掃過整段訊號。上圖是窗的位置，下圖是窗內 RMS 的變化。窗經過運轉區間時，RMS 會明顯上升。

In [7]:
def animate_window(sig, fs, window=0.5, step_seconds=0.02,
                   filename="sliding_window_scan.mp4", poster="sliding_window_scan.png"):
    window_n = int(window * fs)
    step_n = int(step_seconds * fs)
    starts = np.arange(0, len(sig) - window_n, step_n)
    rms = np.sqrt(uniform_filter1d(sig ** 2, window_n))

    fig, axes = plt.subplots(
        2, 1, figsize=(10, 6), sharex=True,
        gridspec_kw={"height_ratios": [2, 1]}, constrained_layout=True,
    )
    axes[0].plot(time, sig, color="0.65", lw=0.6)
    axes[0].set_xlim(0, DURATION)
    axes[0].set_ylim(-3, 3)
    axes[0].set_ylabel("amplitude")
    axes[0].set_title("滑動窗：每次看 0.5 秒")

    rect = plt.Rectangle((0, -3), window, 6, color="tab:orange", alpha=0.2)
    axes[0].add_patch(rect)

    axes[1].plot(time, rms, color="tab:green", lw=1)
    axes[1].set_xlim(0, DURATION)
    axes[1].set_ylim(0, 1.6)
    axes[1].set_xlabel("time [s]")
    axes[1].set_ylabel("RMS")
    point, = axes[1].plot([], [], "o", color="tab:red", ms=5)

    def update(frame):
        start = starts[frame]
        center = start + window_n // 2
        rect.set_x(time[start])
        point.set_data([time[center]], [rms[center]])
        return rect, point

    anim = FuncAnimation(fig, update, frames=len(starts), interval=50, blit=True)
    for i in range(len(starts)):
        update(i)
    fig.savefig(poster, dpi=120, bbox_inches="tight")
    anim.save(
        filename,
        writer="ffmpeg",
        fps=40,
        codec="libx264",
        extra_args=["-pix_fmt", "yuv420p", "-crf", "23"],
    )
    plt.close(fig)

方法四：滑動窗相似度#

第四種做法拿一段已知的運轉波形當模板，讓它跟每個滑動窗比距離。這裡的模板取自第一個運轉區間，長度 0.25 秒，步長 0.05 秒。每個窗先做 z-score，再算歐氏距離；距離最小的前 10% 當成命中。

這個方法不是 DTW。它只是把每個窗正規化後直接比對，所以對相位與波形形狀很敏感。模板從第一個事件來，對其他頻率不同的事件就不一定有效。

In [8]:
window_n = int(0.25 * FS)
step_n = int(0.05 * FS)
template_start = int(1.1 * FS)
template = signal[template_start:template_start + window_n]

windows = sliding_window_view(signal, window_n)[::step_n]

def zscore(v):
    return (v - v.mean()) / (v.std() + 1e-9)

template_z = zscore(template)
distances = np.array([np.linalg.norm(zscore(w) - template_z) for w in windows])
distance_threshold = np.percentile(distances, 10)

m_pattern = np.zeros_like(signal, dtype=bool)
for i, distance in enumerate(distances):
    if distance <= distance_threshold:
        start = i * step_n
        m_pattern[start:start + window_n] = True

fig, axes = plt.subplots(2, 1, figsize=(12, 5), sharex=True,
                         gridspec_kw={"height_ratios": [2, 1]}, constrained_layout=True)
axes[0].plot(time, signal, color="0.65", lw=0.6)
shade(axes[0], m_pattern, color="tab:green", alpha=0.25)
axes[0].set_xlim(0, DURATION)
axes[0].set_ylim(-3, 3)
axes[0].set_ylabel("amplitude")
axes[0].set_title("Pattern matching：z-score 後的歐氏距離")

axes[1].plot(np.arange(len(distances)) * step_n / FS, distances, color="tab:blue", lw=1)
axes[1].axhline(distance_threshold, color="tab:red", ls="--", lw=1)
axes[1].set_xlim(0, DURATION)
axes[1].set_xlabel("time [s]")
axes[1].set_ylabel("distance")

方法五：Rolling energy#

第五種做法看區間能量。先把訊號平方，再做 150 ms 的 moving average，最後對能量取門檻。能量法對振幅敏感，對相位不敏感；它很適合找事件的開始與結束。

代價是窗長與門檻都要調。窗太短會讓輸出跳動，窗太長會讓邊界變鈍。

In [9]:
energy = uniform_filter1d(signal ** 2, int(0.15 * FS))
m_energy = energy > 0.15

量化比較#

下面把四種區間方法與峰值法放在同一張表。Threshold 的 precision 很高，因為它很少誤判；但 recall 受零點切段影響。Peaks 的事件 recall 很好，卻沒有區間長度。Slope 與 pattern 的分數較低，原因是它們對噪聲與模板形狀太敏感。Energy 在這次的訊號上最平衡。

什麼時候用哪一種#

方法看到什麼適合弱點
Threshold振幅快速篩選、線上監測零點切段、門檻難調
Peaks事件中心計算發生次數沒有事件長度
Slope變化率突發高頻、撞擊對噪聲敏感
Pattern波形相似度已知模板的重複事件模板不易泛化
Energy區間能量找開始與結束窗長與門檻要調

如果只需要知道「有沒有發生」，threshold 或 peaks 就夠。如果需要「什麼時候開始、什麼時候結束」，energy 或滑動窗會更合適。實務上通常會把兩三種方法串起來：先用 energy 找候選區間，再用 peaks 或頻譜特徵確認。

小結#

  • 時間域方法各自看到不同的東西。沒有一種方法能同時給你事件、長度與原因。
  • Threshold 與 slope 容易被零點或噪聲切碎。Peaks 只有點，沒有長度。
  • Pattern matching 對模板形狀很敏感；它不等於 DTW。
  • Rolling energy 在這次的訊號上最平衡，但窗長與門檻仍需調整。
  • 下一篇用頻譜看馬達故障。時間域找「什麼時候」，頻譜找「為什麼」。

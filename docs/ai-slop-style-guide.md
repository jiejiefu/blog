# 去 AI 感（AI slop）改寫準則

> **總原則：去 AI 感不是把文章改短，而是刪除沒有資訊增量的文字。**
>
> 每次修改都要回答：有沒有讓資訊更清楚、推理更直接、閱讀更自然？
> 只為了符合字數、降低重複率或改變句型，就不該改。

來源：`content/zh-tw/posts/deepseek-v4-1-flash/index.md` 的實際改寫。
適用於技術文章；不改事實、數字、口徑、引用、公式、圖表。
委託新文章、規劃圖表時，先用 [article-brief.md](article-brief.md) 的提示詞。

## 0. 規則分級

| 層級 | 內容 | 處理 |
|---|---|---|
| P0 | 事實、數字、單位、口徑、引用、公式、限制 | 不可違反；牴觸時退回 |
| P1 | 句長、禁用詞、結構、用詞 | 原則上必須符合 |
| P2 | 節奏、措辭、問句、清單形式 | 依語境判斷 |

**衝突時 P0 > P1 > P2。**
一句話拆短會失去口徑，就讓它超過 25 units，並保留完整條件。

## 1. P0：語意與技術資訊保護

改寫不得省略：

- 比較對象（比誰、比哪一版）
- 時間或版本範圍（9/10 論文 vs 1017 模型卡）
- 計算口徑（每 token、prefill／decode、global／SWA）
- 條件與前提（off-peak、cache hit、warmup）
- 因果與相關的區別
- 不確定性與資訊來源（論文說、官方未公布、vendor-run）
- 限制與反例

⚠️ 反例：把「prefill **每 token** 啟用從 13B 降到 8B」縮成「prefill 啟用降到 8B」。
字數少了，口徑也消失了。

**縮寫測試**：改完後問「拿掉的字，讀者能不能從上下文還原？」
不能，就加回去。多 3 個字比失去口徑便宜。

## 2. P1：句長

### 2.1 單位怎麼算

一個 unit = 1 個 CJK 字 + 1 個英文單字 + 1 個數字序列。

```python
def units(s):
    return (len(re.findall(r"[\u4e00-\u9fff]", s))
            + len(re.findall(r"[A-Za-z]+", s))
            + len(re.findall(r"\d[\d,.]*", s)))
```

- 標點、空格、Markdown 標記不計。
- 不拆：長英文術語、API 名稱、檔名、版本號。
- 不計入句長：front matter、code fence、`$$` 公式、逐字引用（blockquote）。
- 表格不計句長，但掃禁用詞，cell >35 units 給 WARNING。
- 作者自己寫的 caption 要計，>60 units 給 WARNING。caption 是資訊單元，不是句子。

散文 ≤25 units；表格 cell／術語列舉 ≤35；caption ≤60。
**語意完整性優先於數字**：拆了會改變指涉範圍，就不要拆。

### 2.2 其他 P1

- 粗體 ≤30 處／篇，只標關鍵數字或結論。
- 不用「我／我們／筆者」；不自嘲。
- 全形標點；「」引號；少用破折號做戲劇停頓。
- 用詞：資料（非數據）、智慧（非智能）、沙箱、載入、設定、發佈。
- 絕對禁用詞 0（見 §3.1）。

## 3. P1：禁用詞分兩級

### 3.1 絕對禁用（出現就改）

| 不要寫 | 改成 |
|---|---|
| 深入探討、雙刃劍 | 直接給結論；分別講兩邊的成本 |
| 眾所周知、顯而易見 | 刪 |
| 不可否認 | 刪 |
| 見證了、畫卷、浪潮、里程碑、未來可期 | 講實際發生什麼 |
| 革命性、顛覆性、前所未有、重新定義、劃時代 | 給數字，或拿掉 |
| 引人入勝 | 講哪裡有趣 |
| 不僅…而且… | 拆兩句 |
| 「這不是 X，而是 Y」 | 全篇最多一次 |
| 「真正的問題是…」 | 直接問、直接答 |

### 3.2 情境禁用（有邏輯功能才留）

| 詞 | 判斷 |
|---|---|
| 此外、另外、同時 | 純補充就刪；真的並列兩個獨立重點可留 |
| 值得注意的是、更重要的是 | 幾乎都可刪；後文是反直覺結論且刪了會漏看，才留 |
| 總而言之、綜上所述、由此可見 | 結論段可刪；要標記推論終點才留 |
| 換句話說 | 只是重述就刪；換成更精確的說法才留 |
| 首先／其次／最後 | 預設改內容分點；真的是步驟順序才留 |

**原則：刪掉後語意不變 → 刪；有明確邏輯功能 → 留。**
不要把情境禁用當成 zero-tolerance 清單。

## 4. P2：風格指引（不是 KPI）

- 句長中位數 6–8 是觀察值，不是目標。
- 長短句交錯；不要每句都 7 字。
- 問句 2–3 個是上限，不是配額；不確定就不要用。
- 定義放在術語第一次出現處。
- 清單不要用「還有…」「加上…」串接，直接列。
- 結尾只收斂事實，不昇華、不加願景。
- 每節開頭直接進事實，不寫「本節將說明」。
- 段落長度只觀察，不設句數上限；硬拆會製造短促的節奏。

## 5. 五個逐句動作

1. **刪過渡**：句首的「值得注意的是」「換句話說」整句刪，不動後文。
2. **拆句**：一個句號一個主張；逗號超過 3 個就拆。
3. **主詞具體化**：「這意味著」→ 換成誰／什麼意味著。
4. **評價→事實**：「大幅提升」→ `+11.1`；「非常快」→ `42.3`。
5. **抽象→動作**：「進行了優化」→ 改了哪個 kernel／哪個決策。

## 6. 去重複：以語意為單位

- **不設字頻上限。** KV cache、prefill、decode、attention、kernel 這類必要術語不限次數。
- 要查的是「同一件事講了兩次」，不是「同一個詞出現兩次」。
- 高頻詞只在兩種情況處理：
  1. 同一句群裡同義改寫（換句話說、也就是說）。
  2. 同一結論在相鄰章節重複。
- 手法：
  - TL;DR 只給結論；正文換角度或補新資訊。
  - 標題已講的數字，該節第一段不再講。
  - 表格已列的，正文只解釋「為什麼」。
  - 同一限制只在最相關那節完整寫。

3-gram Jaccard ≥0.5 只當**篩選器**，不是判決。
同語意不同措辭仍算重複；相似度低也可能是換句話說。

## 7. 改寫前後差異檢查（P0 驗收）

| 項目 | 條件 |
|---|---|
| 數字 | 集合一致；刻意刪除的重複數字要記錄 |
| 單位 | bytes／KB／GB／%、tokens、ms 不變 |
| 專有名詞 | 版本號、benchmark 名、模型名不遺失 |
| 引用 | 來源與歸屬保留 |
| 圖表 | shortcode 數量、路徑、順序不變 |
| 公式 | `$$` 區塊數量與內容不變 |
| 限制 | 限制章節的條目沒有被刪或弱化 |
| 章節 | 編號與錨點不變 |

```sh
cp content/zh-tw/posts/<slug>/index.md /tmp/before.md
# ...改寫...
cp content/zh-tw/posts/<slug>/index.md /tmp/after.md

python3 - <<'PY'
import re, collections
unit = r"\d[\d,.]*\s?(?:B|MB|GB|KB|TB|bytes|tokens?|%|ms|s|x)?"
def nums(p):
    return collections.Counter(re.findall(unit, open(p, encoding="utf-8").read()))
a, b = nums("/tmp/before.md"), nums("/tmp/after.md")
print("只在 before:", dict((a - b).most_common(30)))
print("只在 after :", dict((b - a).most_common(30)))
PY

for f in /tmp/before.md /tmp/after.md; do
  printf '%s figure=%s mermaid=%s math=%s table=%s\n' "$f" \
    "$(rg -o '\{\{< figure' "$f" | wc -l | tr -d ' ')" \
    "$(rg -o '\{\{< mermaid' "$f" | wc -l | tr -d ' ')" \
    "$(rg -o '^\$\$' "$f" | wc -l | tr -d ' ')" \
    "$(rg -o '^\|' "$f" | wc -l | tr -d ' ')"
done
```

`a - b` 一定會有大量預期差異。重點是逐項確認每個消失的數字都是刻意的。

## 8. 驗收

```sh
rm -rf public && hugo --minify          # 必須 0 warning
python3 scripts/check_slug_style.py     # OK
python3 scripts/ai_slop_check.py content/zh-tw/posts/<slug>/index.md
```

腳本輸出分三級，**不要讓所有問題都變同等嚴重**：

| 級別 | 內容 | 行為 |
|---|---|---|
| ERROR | >35 units、絕對禁用詞、第一人稱 | exit 1，必須修 |
| WARNING | 26–35 units、情境禁用詞、粗體 >30、caption >60、表格 cell >35 | exit 0，人工判斷 |
| INFO | 句數、>25 數、中位數、粗體數、表格列數、最長散文段 | 觀察 |

腳本只做 triage。WARNING 不是自動要改，ERROR 才擋。
逐字引用豁免句長與禁用詞（不能改別人的話）；表格不計句長，但會掃禁用詞與長 cell。
caption 的上限放寬到 60，因為它常要交代口徑與限制，砍短等於砍 P0。

回歸基準（DeepSeek-V4.1-Flash 那篇，`d5b18df` → 改寫後）：

| 指標 | 改寫前 | 改寫後 |
|---|---:|---:|
| 句數 | 351 | 513 |
| >25 units | 81 | **0** |
| >35 units（ERROR） | 27 | **0** |
| 中位數 | 16 | 10 |
| 粗體 | 210 | **28** |
| 表格列 | 81 | 81 |

句數上升是拆句的結果，不是文章變長。

## 10. 反例

- 不要自嘲，或加「能力有限」的謙辭。
- 不要為了字數砍掉口徑、條件或因果。
- 不要為了降低重複率，把術語換成同義詞。
- 不要把「不確定」寫成「確定」。
- 不要把所有段落改成同一種節奏。
- 不要把 P1／P2 當成全部必須達成的 KPI。
- 不要在文章裡寫「本文由 AI 協助」。

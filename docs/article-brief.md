# 文章製作 brief

> 這份文件是「委託階段」的提示詞。改寫與驗收的規則在
> [ai-slop-style-guide.md](ai-slop-style-guide.md)，這裡不重複。

## 什麼時候用

- 開新文章
- 補圖表
- 圖片健檢
- 完稿前檢查

## 適用範圍

主題不限 GitHub。論文、產品、事件、工具、事故复盘都可以。
下面的範例用 GitHub 專案，模板本身不綁定。

## 提示 1：開新文章

```text
我要新增一篇文章，主題：<主題>。

風格參考 content/zh-tw/posts/rea-reverse-engineer-anything/index.md：
- 詳細但不廢話，先給 TL;DR，每節開頭先講結論
- 架構圖、流程圖、圖表放在對應段落，不要集中在附錄
- 封面 cover.jpg 比照該篇的終端機／藍圖風格
- 內文圖放 images/，命名 01_xxx.webp

動筆前先給我 5–8 個圖表提案：
- 圖名
- 要回答的問題
- 資料來源
- 放在哪一節
- 形式（流程圖／長條／折線／時序／熱圖）

缺資料或圖片我會幫你找。
```

三個重點：

- 先提案，再寫正文。寫完才發現沒有圖，通常會補出裝飾性插圖。
- 參考文章只借結構與密度，不抄內容。
- 封面風格沿用終端機／藍圖，和既有兩篇一致。

## 提示 2：補圖

```text
這篇還可以畫哪些圖表？上限 8 個，用 Python、Plotly 或 Mermaid。
每個提案寫：圖名、要回答的問題、資料來源、放哪一節、形式。
沒有資料支撐的不要提。先不要動筆，等我選。
```

判斷一張圖該不該存在，問四個問題：

1. 它回答哪個問題？
2. 資料從哪來？
3. 放在哪一段之後？
4. 拿掉它，讀者會少知道什麼？

第 4 題答不出來，就不要畫。

## 提示 3：圖片健檢

```text
檢查 images/ 的圖：
1. 文字太小 → 放大（1376px 畫布最小 18px）
2. 內容單調 → 補資料點、註解或分組，不要加裝飾
3. 一張圖只講一件事
4. caption 要寫口徑、範圍與限制
5. 對比不足 → 提高對比，不要只靠顏色區分資訊
列出要改的圖與原因，改完再回報。
```

## 提示 4：AI 感檢查

```text
檢查全文的「不是…而是…」與禁用詞，全篇最多一次。
執行 python3 scripts/ai_slop_check.py content/zh-tw/posts/<slug>/index.md
ERROR 必須修；WARNING 逐條判斷，不要機械式改寫。
```

## 圖表選擇

| 內容型態 | 形式 |
|---|---|
| 系統組成、資料流 | 架構圖、流程圖 |
| 多步協定、狀態轉移 | sequence diagram、state diagram |
| 版本演進、事發順序 | timeline |
| 數量比較 | 長條圖、折線圖 |
| 資源帳、成本拆分 | stacked bar、Sankey |
| 取捨、二維定位 | scatter、quadrant |
| 需要讀者自己探索 | Plotly |

## 圖表密度（建議值）

- 每 400–600 字一個視覺，或每 2–3 個小節一個。
- 連續三個小節沒有視覺，通常表示其中一節可以合併。
- 圖不是裝飾。沒有新資訊就不放。
- 同一張圖不要為了密度重複使用。

## 讀者留存

- TL;DR ≤10 行，只給結論。
- 每節第一句是結論，不是背景。
- 標題單獨拿出來也讀得懂。
- 長段先刪重複，再考慮拆。
- 每節只解決一個問題。
- 結尾收事實，不昇華。

## 產圖工具鏈

| 形式 | 工具 | 產出 |
|---|---|---|
| 流程、狀態、時序 | `{{< mermaid >}}` | 頁內 SVG |
| 定量比較 | matplotlib + `scripts/image_utils.py` | WebP |
| 互動探索 | `{{< plotly >}}` | JSON + CDN |
| 架構圖 | 手繪 SVG | WebP |
| 封面 | ImageMagick | JPEG |

定量圖一律用 `save_figure_webp()` 直出 WebP，PNG 只留在暫存目錄。

### 尺寸與格式

| 用途 | 格式 | 尺寸 |
|---|---|---|
| 內文圖 | WebP q82 | 維持 1376px 寬 |
| 封面 | JPEG q85 | 1200px 寬 |
| 互動圖 | Plotly JSON | 不產圖檔 |

- 內文圖不要縮到 1000px，retina 會糊。
- 封面用 JPEG。Facebook、LinkedIn 對 WebP 的 og:image 支援不完整。
- 內文圖只放 `content/zh-tw/posts/<slug>/images/`。
  en 版靠 Hugo 跨 bundle 解析，不需要複製。

### 圖片可讀性

- 以 1376px 畫布計，最小字級 18px。
- 在 720px 預覽寬（PaperMod 內文寬）仍要能讀。
- 文字對比 ≥4.5:1。
- 一張圖一個主張。小圖不要塞三件事。
- 座標軸要有單位；caption 要寫口徑與限制。
- alt 寫「讀者能從圖得到什麼」，不要寫「示意圖」。

## 寫作順序

1. 蒐集數字與來源，標記不確定。
2. 列 5–8 個圖表提案，選 6–9 個。
3. 寫 TL;DR 與每節結論句。
4. 補正文，圖放在對應段落後。
5. 產圖、健檢。
6. 跑 `ai_slop_check` 與 `hugo`。
7. 需要改寫時回到 `ai-slop-style-guide.md`。

## 完稿檢查

```sh
python3 scripts/ai_slop_check.py content/zh-tw/posts/<slug>/index.md
python3 scripts/check_slug_style.py
rm -rf public && hugo --minify

# 「不是…而是」全篇 ≤1
rg -c '不是.{0,30}而是' content/zh-tw/posts/<slug>/index.md
```

另外確認：

- 禁用詞 0。
- 每個 `src="images/..."` 都真的存在。
- 封面 `og:image` 指向 JPEG。
- 圖表順序與正文一致。

## 常見失敗

| 症狀 | 原因 | 修法 |
|---|---|---|
| 圖很多但讀完沒印象 | 圖在重複正文 | 每張圖只保留正文沒說的資訊 |
| 讀者放大才看得懂 | 字級太小 | 1376px 畫布最小 18px |
| 文章很長但沒有重點 | 每節沒有結論句 | 每節第一句先給結論 |
| 封面和內文像兩篇文 | 風格沒對齊 | 沿用終端機／藍圖，色票一致 |
| 段落牆 | 一段塞多個主張 | 先刪重複，再拆 |

## 不要做的事

- 不要先寫完再補圖。
- 不要用裝飾性插圖填空。
- 不要把圖集中在附錄。
- 不要為了密度重複同一張圖。
- 不要編造數字或來源。
